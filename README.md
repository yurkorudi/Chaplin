# Chaplin Cinema — локальна презентація на Windows

Наявний Flask-проєкт, доповнений бронюванням, замовленнями, оплатою, магазином і касою. Основні сторінки та брендинг збережено. Для стабільності залишено Flask-Admin; каса має окремий інтерфейс.

## Запуск

З кореня проєкту двічі відкрийте **`run.bat`** або виконайте в PowerShell:

```powershell
.\run.bat
```

Сайт: **http://127.0.0.1:5000**. Перевірка працездатності: http://127.0.0.1:5000/healthz.

Сценарій перевіряє залежності, за потреби встановлює їх у `venv`, запускає окремий MySQL, ініціалізує/оновлює схему, доповнює демонстраційні дані й запускає Flask без debug. Якщо сайт уже працює, другий екземпляр не запускається. Перший запуск із чистим Python потребує доступу до PyPI.

На цьому ПК використано **Python 3.14.6 і встановлений MySQL Server 8.0.46**. MySQL працює як окремий прихований процес:

- адреса `127.0.0.1:3307`, база `chaplin_demo`;
- файли `.local/mysql`, логи `.local/mysql.stderr.log`;
- системні служби, сторонні бази й глобальні паролі не змінюються;
- власний випадковий пароль користувача БД та ключ Flask зберігаються у `.env`;
- адміністративний пароль **цього окремого екземпляра** — у `.local/mysql-root.txt`;
- `.env` і `.local/` виключено з Git.

Якщо MySQL відсутній, встановіть MySQL Server 8.0 з [офіційного джерела](https://dev.mysql.com/downloads/mysql/8.0.html). Автоматичний локальний сценарій перевірено для 8.0, не для 8.4/9.x. Якщо шлях відрізняється, задайте `MYSQLD_PATH` у середовищі. Альтернатива — власна локальна MySQL-база з `DATABASE_URL` у `.env`. Приклад параметрів — `.env.example`; автоматичний сценарій сам генерує справжній `.env`, копіювати приклад перед першим запуском не потрібно.

Окремі команди:

```powershell
.\venv\Scripts\python.exe setup_local.py
.\venv\Scripts\python.exe app.py
```

Для перезапуску фонового сайту після редагування коду: `powershell -File .\restart_demo.ps1`. Скрипт перевіряє, що порт 5000 зайнятий саме `app.py` цього проєкту; сторонній процес не зупиняє. Логи Flask — `.local/flask.stderr.log`. При запуску через `run.bat` сайт зупиняється Ctrl+C; MySQL залишається працювати, його дані зберігаються.

## Облікові записи

Випадкові локальні паролі записані **лише у `.local/demo-accounts.txt`**. Повторне наповнення не скидає паролі.

| Логін | Роль | Доступ |
|---|---|---|
| `demo` | покупець | квитки, магазин, власний профіль і замовлення |
| `admin` | адміністратор | усі розділи `/admin/`, каса `/manager/` |
| `manager` | касир | `/manager/`, самовивіз `/manager/shop`; лише призначений Chaplin Київ |

Вхід для всіх ролей: `/login`. Старі адреси входу адміністратора та менеджера перенаправляють сюди. Менеджеру можна змінити призначений кінотеатр через керування користувачами.

## Сценарій презентації

1. Відкрийте головну, виберіть Київ або Львів. У містах різні часи та добірки сеансів.
2. Увійдіть як `demo`, відкрийте **Розклад**, виберіть фільм та час сеансу.
3. На схемі оберіть місця. VIP має інший колір і ціну. На вузьких екранах схема прокручується всередині блоку, а не вся сторінка.
4. Натисніть **Придбати**, перевірте склад і суму. Резерв дійсний 10 хвилин.
5. На сторінці замовлення натисніть **Імітувати успішну оплату**. Дані банківської картки не потрібні.
6. Натисніть **Завантажити PDF-квитки**. Кожне місце має окрему сторінку A5 та непрозорий QR-ідентифікатор. PDF також доступний у профілі через деталі замовлення.
7. У магазині оберіть товар, змініть кількість у кошику й оформіть доставку Новою поштою або самовивіз. Доставка допускає тільки онлайн-оплату; для самовивозу доступна оплата в кінотеатрі.
8. Як `manager` відкрийте `/manager/`, оберіть сеанс і місця, спосіб `cash`/`card`, підтвердіть демо-продаж і завантажте PDF. QR-ідентифікатор можна перевірити через форму каси.
9. Замовлення самовивозу обробляються у `/manager/shop`. Касир бачить тільки свій кінотеатр, може прийняти демо-оплату та підтвердити видачу.
10. Як `admin` відкрийте `/admin/`. Додавання сеансу з послідовністю місто → кінотеатр → зал → фільм доступне через **Додати сеанс** на головній панелі: `/admin/schedule/new`. Перетини перевіряються з буфером підготовки 15 хвилин. Адміністратор керує товарами, категоріями, користувачами, фільмами, залами та бачить квитки й замовлення; для магазину є дії «готове до видачі», «відправлено», скасування неоплачених замовлень.

Усі касові продажі у поточному локальному режимі — **демонстраційні, без фіскалізації**.

## Дані та схема

`seed_demo.py` ідемпотентно доповнює дані: два міста, два кінотеатри, чотири зали, шість фільмів, сеанси на поточну дату та наступні 7 днів, 20 товарів у п’яти категоріях. Геометрія залів: 6 × 10, останній ряд VIP. Частково зайняті місця створюються через звичайну логіку оплаченого демозамовлення. Наявні записи не очищаються; конфліктні часові слоти пропускаються.

`schema.py` створює відсутні таблиці та додає необхідні поля/індекси без видалення наявних таблиць. Перед оновленням непорожньої локальної БД створюється SQL-копія у `.local/backups/` через `mysqldump --single-transaction`. При виявленні дубльованих старих квитків міграція зупиняється для ручної перевірки, не видаляючи записи. Для відновлення використовуйте копію на окремій БД і перевірте її перед заміною робочих даних.

Існуючі сутності `users`, `cinemas`, `halls`, `films`, `sessions`, `seats`, `tickets`, `images` збережено. Додано `orders`, `order_items`, `seat_reservations`, `products`, `categories`, `payment_receipts`. Ціни зберігаються як `NUMERIC`; унікальні обмеження захищають позицію місця у сеансі, квиток та ідентифікатор підтвердженого платежу.

Основні нові модулі: `commerce.py` (бронювання, профіль, магазин і каса), `admin_support.py`, `admin_forms.py`, `tickets_pdf.py`, `liqpay_payment.py`, `config.py`, `setup_local.py`, `schema.py`, `seed_demo.py`. Інтерфейси додано в `templates/`, адаптивні доповнення — у `static/css/commerce.css` та `responsive.css`. `createdb.py` залишено як сумісну точку входу до безпечної локальної ініціалізації.

## Оплата і межі інтеграцій

`PAYMENT_DEMO_MODE=true` в автоматично згенерованому локальному `.env` дозволяє імітацію лише з loopback-адреси та після перевірки власника замовлення/ролі. Повторний платіж не дублює квитки. Прострочений резерв не можна оплатити; місця стають доступними автоматично за строком дії. Перенаправлення браузера не є підтвердженням оплати.

Для реального LiqPay підготовлено серверне формування checkout і перевірку callback **API v7 / SHA3-256** за [офіційною документацією](https://www.liqpay.ua/uk/doc/api/callback). Потрібно встановити `PAYMENT_DEMO_MODE=false`, власні `LIQPAY_PUBLIC_KEY`, `LIQPAY_PRIVATE_KEY`, `PUBLIC_BASE_URL=https://...`, HTTPS-cookie та доступну банку серверну адресу `/payments/liqpay/callback`. Сума, валюта, магазин, дія, версія API та номер замовлення перевіряються. Callback використовує підпис провайдера; браузерні форми залишаються під CSRF-захистом. Пізні платежі або повернення отримують статус `payment_review`; автоматичне повернення грошей не реалізовано. **Реальна транзакція з банком не виконувалася.**

ПРРО не підключено: `fiscal_status=not_fiscalized` є точкою інтеграції, а не фіскальним підтвердженням. Без деморежиму касове підтвердження нового платежу відхиляється. Нова пошта використовує ручне введення міста й відділення/поштомата; API-довідники, накладні та розрахунок доставки не підключені.

Небезпечне довільне створення/редагування оплачених квитків і замовлень не доступне. Видалення основних пов’язаних сутностей обмежене для збереження історії. Повний перехід від Flask-Admin до власної панелі не виконувався.

Раніше закомічені віддалені облікові дані та ключі потрібно **відкликати/замінити у відповідних сервісах**: їх видалення з поточного коду не прибирає їх із Git-історії. Старий локальний `password.txt` перенесено у `.local/legacy-passwords.txt`, без публікації його вмісту. Демоакаунти та сервер Flask призначені для локальної презентації.

## Перевірки

```powershell
.\tests.bat
```

Тести створюють нову тимчасову MySQL-базу `chaplin_test_<випадковий суфікс>` на окремому локальному сервері 3307, не змінюють `chaplin_demo` й прибирають тільки свою тестову базу. SQLite не використовується. Потрібен попередній запуск `setup_local.py`.

Перевірено: головні маршрути; реєстрацію та хешування паролів; оновлення профілю; CSRF і ролі; серверну ціну звичайних/VIP-місць; недійсні місця; розділення міст; конкуренцію двох бронювань; прострочення резерву; локальне обмеження демооплати; повторну оплату; доступ до чужих замовлень/PDF; створення PDF; залишки, ціни й доставку магазину; скасування неоплаченого замовлення; форми та створення/редагування товару в адмінпанелі; конфлікти сеансів; касові продажі й самовивіз; ідемпотентність seed; підпис, суму/валюту, повтори та повернення в LiqPay callback. Офіційний приклад підпису v7 перевіряється окремим тестом.

Браузерні перевірки основних відкритих сторінок виконано на 320, 375, 390, 430, 768, 1024 і 1280 px. PDF відрендерено та переглянуто. Конкретні фінальні результати та залишкові обмеження наведено у `PRESENTATION_REPORT.md`.
